# Google Sheets API Setup

Данная директория содержит серверный код (code.gs) для развертывания в среде Google Apps Script. Скрипт функционирует как изолированный REST API, принимающий результаты тестирования с фронтенда и осуществляющий их структурированную запись в таблицу Google Sheets.

## Инструкция по развертыванию

1. Создайте целевую Google Таблицу и откройте её.
2. Перейдите в верхнем меню в раздел Расширения (Extensions) -> Apps Script.
3. Удалите стандартный шаблонный код и вставьте содержимое файла code.gs.
4. Нажмите кнопку Сохранить (иконка дискеты).
5. Нажмите кнопку Начать развертывание (Deploy) -> Новое развертывание (New deployment).
6. В открывшемся окне выберите тип конфигурации: Веб-приложение (Web app).
7. Задайте параметры конфигурации:
   - Запуск от имени: Вы (Ваш аккаунт Google).
   - У кого есть доступ: Все (Anyone). Данный параметр обязателен, чтобы POST-запросы со стороны внешнего сайта могли обрабатываться скриптом.
8. Нажмите Развернуть (Deploy) и скопируйте сгенерированный URL вида:
   https://script.google.com/macros/s/.../exec
9. Вставьте этот URL в файл js/app.js в поле GOOGLE_SCRIPT_URL внутри блока CONFIG.

Примечание: При внесении любых изменений в код code.gs необходимо создавать новую версию развертывания (Управление развертываниями -> Редактировать -> Версия: Новая версия). В противном случае Google Apps Script продолжит исполнять закэшированную предыдущую версию кода.

## Архитектурные особенности скрипта

- Строгая структура (Schema): Распределение данных по столбцам жестко регламентировано константой HEADERS, что предотвращает смещение ячеек при отправке данных.
- Автоматическая инициализация (Idempotent Headers): При первом запуске на пустом листе скрипт самостоятельно генерирует строку заголовков, применяет к ней стилизацию и выполняет закрепление строки (Frozen Row).
- Защита от дублирования записей (Anti-Flood): Скрипт осуществляет валидацию уникального идентификатора запроса (submission_id). При повторной отправке идентичного пакета транзакция блокируется, предотвращая замусоривание таблицы.
- Поколоночный сбор ответов: Ответы на каждый из 9 вопросов опросника декомпозируются в отдельные целевые столбцы (Вопрос 1 ... Вопрос 9) для упрощения последующего статистического анализа.
- Резервное копирование (JSON Payload): Полный исходный пакет данных от браузера сериализуется и записывается в финальный столбец строки в виде сырого JSON. Это обеспечивает сохранность данных при изменении методологии расчета шкал в будущем.

## Спецификация входящего JSON (API Payload)

Скрипт обрабатывает входящие POST-запросы со следующей структурой тела:

{
  "submission_id": "tsqm_1716556200",
  "name": "Иванов Иван Иванович",
  "date": "24.05.2026, 16:10:00",
  "effectiveness": 75,
  "convenience": 83,
  "global": 66,
  "raw_answers": {
    "q1": 4,
    "q2": 5,
    "q3": 4,
    "q4": 5,
    "q5": 4,
    "q6": 4,
    "q7": "—",
    "q8": "—",
    "q9": 5
  }
}
